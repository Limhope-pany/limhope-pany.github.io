一.题目介绍

网络存在源码泄露，需要找到源码文件名

1.1 考点

  • 日志分析
  • PHP反序列

1.2 环境文件

下载附件，解压数据包

二.解题步骤：

问（1）

2.1-1 开启环境得到一个附件日志分析.zip，解压得到access.log，用记事本打开有如下信息

2.1-2 筛选有效访问记录

·源码泄露需要满足：客户端发起 GET 请求 + 服务器返回状态码 200（访问成功） 使用快捷键 Ctrl+F 检索关键词：200，一直点击【查找下一个】，直到日志中有类似www%2ezip、www%2erar出现

2.1-3 可以找到这条关键记录

表明黑客成功访问并下载了/www.zip 文件

2.1-4 所以泄露的源码文件名为：www.zip，即NSSCTF{www.zip}

问（2） 解题步骤：

2.2-1 筛选成功包，即200状态码，不要看扫描包，即404状态码

2.2-2 识别漏洞模式：目录穿越+文件写入

攻击请求一般是带参数的请求，不是直接访问文件，格式类似于： GET /?filename=大量..%2Ftmp%2Fsess_car&content=xxx HTTP/1.1 或者/?file=xxx HTTP/1.1

2.2-3 使用快捷键 Ctrl+F 检索关键词：？filename=，一直点击【查找下一个】直到看见题目答案

2.2-4 通过查找可以找到关键记录

2.2-5 表明黑客写入的文件为sess_car，即NSSCTF{sess_car}

·URL编码：

  • filename 参数：指定要操作的文件路径
  • ..%2F = URL 编码的 ../ ，目录穿越（路径遍历），突破网站根目录，访问系统/tmp临时目录
  • content 参数：写入文件的内容
  • 目录：/tmp/

问（3） 解题步骤：

2.3-1 打开 access.log 日志文件，筛选攻击流量，找200状态码且请求URL带有参数（？xxx=）

2.3-2 检索关键词：flag、splFileObject

2.3-3 找到完整URL参数行，日志GET请求格式：

GET /?filename=..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2Ftmp%2Fsess_car&content=func%7CN%3Bfiles%7Ca%3A2%3A%7Bs%3A8%3A%22filename%22%3Bs%3A16%3A%22.%2Ffiles%2Ffilename%22%3Bs%3A20%3A%22call_user_func_array%22%3Bs%3A28%3A%22.%2Ffiles%2Fcall_user_func_array%22%3B%7Dpaths%7Ca%3A1%3A%7Bs%3A5%3A%22%2Fflag%22%3Bs%3A13%3A%22SplFileObject%22%3B%7D HTTP/1.1" 302 879 "-" "python-requests/2.26.0"， content=后面的内容就是攻击载荷

2.3-4 对paths%7Ca%3A1%3A%7Bs%3A5%3A%22%2Fflag%22%3Bs%3A13%3A%22SplFileObject%22%3B%7D进行解密

得到完整明文：paths|a:1:{s:5:"/flag";s:13:"SplFileObject";}

  • s:13:"SplFileObject"中的SplFileObject就是类名 2.3-5 所以NSSCTF{SplFileObject}

三.相关知识点

3.1 PHP反序列化：

  • PHP反序列化就是黑客把一段构造好的数据（序列化字符串）通过 GET 参数传给网站。网站代码调用unserialize()函数，自动创建对应类的对象，触发危险行为（读取文件）。

3.2 PHP反序列化固定格式（传统）：

  • 0：数字：“类名”：属性数量：{内容}
  • URL编码：0：会变成0%3A；“变成%22，必须解密才能看懂 本题中，考查的是自定义管道分割参数
  • paths：功能标识
  • a:1:数组，包含1组键值
  • s:5:"/flag"：键，代表目标文件路径（秘密文件/flag）
  • s:13:"SplFileObject"：值，代表用来读取该文件的PHP类

3.3 完整攻击链：

第一阶段：踩点 —— 源码泄露（问1）

3.3-1 黑客在做什么？

刚拿到目标网站，不知道里面有什么漏洞。黑客用扫描器批量探测常见的源码备份文件，看看网站根目录有没有不小心留下的压缩包。 日志特征 扫描器爆破了一大堆备份文件名： /index.php.zip → 404（不存在） /index.php.rar → 404 /web.zip → 404 /root.zip → 404 ... /www.zip → 200 命中！ 日志里写成 www%2ezip，因为扫描器把.编码成%2e绕过 WAF。

3.3-2 黑客得到了什么？

成功下载到 www.zip，解压后拿到网站全部源代码。 → 这一步是整个攻击的起点：有了源码，黑客才能在本地审计出后面的漏洞。

第二阶段：拿权限 —— 文件写入（问2）

3.3-3 黑客在做什么？

拿到源码后审计，发现网站有个文件写入功能（比如上传、session 保存、模板渲染），可以控制写入的文件名和内容。 黑客利用目录穿越（../），把文件写到网站根目录之外的系统临时目录 /tmp。 日志特征 请求里带 filename 和 content 两个参数： GET /?filename=..%2F..%2F..%2F..%2Ftmp%2Fsess_car&content=... HTTP/1.1 200 解码后： filename=../../../../tmp/sess_car content=（恶意内容） ..%2F = ../ ：一层层往上跳目录，跳出网站根目录 最终落到系统临时目录 /tmp/sess_car

3.3-4 黑客为什么写这个文件？

sess_car 是一个伪造的 session 文件。 PHP 的 session 默认存在/tmp下，文件名格式 sess_xxx。黑客提前往里面写入精心构造的反序列化数据，为第三步做准备。

第三阶段：拿 flag—— 反序列化读文件（问3）

3.3-5 黑客在做什么？

网站还有一个反序列化漏洞：会读取 session 文件内容，然后调用 unserialize() 解析。 黑客第二步已经把恶意序列化数据写进了 /tmp/sess_car，现在触发反序列化，让服务器执行他构造的逻辑。 日志特征 请求参数里是一长串编码后的序列化数据，关键片段： paths|a:1:{s:5:"/flag";s:13:"SplFileObject";} /flag：要读取的秘密文件路径 SplFileObject：PHP 内置的文件操作类

3.3-6 攻击原理（PHP 原生类反序列化）

黑客不需要自己写 webshell，直接利用 PHP 自带的 SplFileObject 类：

  • unserialize() 解析数据，自动创建一个 SplFileObject 对象
  • 创建对象时传入 /flag 作为参数
  • SplFileObject 自动打开并读取 /flag 文件内容
  • 内容回显在响应里，黑客直接拿到 flag 3.2-7 为什么用SplFileObject不用SplFileInfo？
  • SplFileInfo只能看文件大小、修改时间，读不了内容
  • SplFileObject继承自它，真正能读取文件内容，符合 "读取秘密文件"。
