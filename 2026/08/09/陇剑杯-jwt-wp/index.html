三.相关知识点

3.1 JWT识别特征

  • 开头固定：eyJ
  • 格式：三段base64编码字符串,2个小数点隔开
  • 一般存放于Cookie的Token参数、Authorization请求头

3.2 注意

  • 不要选用id=10086的Token，该令牌属于普通用户，10087才是黑客篡改后的管理员账号
  • 攻击包是访问/exec接口、准备执行系统命令的TCP流
  • 严格区分普通PHP会话Cookie和JWT‑token参数

3.3 什么是Token？

Token直译叫令牌，本质是一串加密/编码后的字符串，用来证明你的身份、代替密码做登录凭证，网站靠Token识别管理员身份，从而可以调用命令执行接口。

3.4 常见的Token

3.4.1身份认证类

  • Session-Token（会话令牌）：包括PHP‑SESSID、JSESSIONID
  • Bearer Token（持有者令牌）：API、接口最常用，HTTP请求头 Authorization: Bearer xxx，JWT只是Bearer‑Token最常见的一种
  • Access‑Token（访问令牌）：短期有效，用来调用接口
  • Refresh‑Token（刷新令牌）：长期有效，access失效后换新令牌 多用于微信、QQ、第三方登录、小程序、APP 授权
  • API‑Token/Api‑Key：后台接口密钥，固定字符串，用于程序之间鉴权，例如阿里云、GitHub、各种开发者接口密钥

3.4.2 安全功能类

  • CSRF‑Token（跨站请求伪造令牌）：网站表单里的随机串，防止跨站伪造提交请求。
  • Reset‑Token（密码重置令牌）：找回密码链接携带的一次性令牌。
  • Captcha‑Token 验证码令牌：用来校验人机验证码。

3.4.3 移动端&开发常用

  • Device‑Token（设备令牌）：手机推送标识，用于苹果 APNs、安卓推送，用来给指定设备推送消息
  • Nonce‑Token 随机一次性令牌：仅单次使用，防重放攻击

3.5 普通用户 VS 黑客攻击包

看请求的url路径

  • 路径是 /identity——普通登录包，token=10086
  • 路径是 /exec?command=whoami——黑客攻击包，Token=10087

3.6 什么是载荷？

载荷payload，就是真正用来达成攻击目的的核心代码、命令、数据。 攻击包分为两部分：外壳（触发漏洞的代码）+载荷

3.7 问（5）命令解析

  • gcc：LinuxC语言编译器
  • -shared -fPIC：编译生成动态库（.so）的参数
  • /tmp/1.c：之前写入的恶意源码（问4的1.c）
  • -o /tmp/looter.so：-o指定输出文件，编译产出的恶意so文件名：looter.so

3.8 易混点提醒

  • 1.c是源码文件（问4）；looter.so是编译之后得到的so 动态库文件（问5），两个不要弄混。
  • so文件是服务器gcc编译生成，不是黑客上传过来的，所以没有multipart表单上传包，全部依靠/exec接口执行系统命令完成。

3.9 问（6）命令解析

  • echo /tmp/looter.so：输出恶意so文件完整路径
  • '> /etc/pam.d/common‑auth'：将输出重定向写入该配置文件，修改这个文件，完成恶意库预加载持久化
  • /etc/pam.d/common‑auth：就是被修改文件的绝对路径 common‑auth：所有登录通用认证配置文件

3.10 什么是PAM

PAM=Pluggable Authentication Modules，可插拔认证模块 是 Linux 系统的一套登录认证框架。 简单来说就是：管系统登录的，SSH登录、本地终端、su、sudo、图形界面登录全都由它管控。

PAM 能干什么

  • 校验登录密码
  • 限制登录时间段、允许/禁止用户
  • 双人认证、短信验证码登录
  • 记录登录日志
  • 被攻击者利用植入登录后门
